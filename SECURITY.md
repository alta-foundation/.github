# Security policy

ALTA repositories are under active development. Unless a repository says otherwise, there is no published support matrix or response-time commitment. A security fix may require a new release, a configuration change, or a notice about an affected version.

## Report a vulnerability privately

Use **Security → Report a vulnerability** in the affected repository when that option is available. Include the affected version or commit, reproduction steps, impact, and any safe proof of concept. Please do not include live credentials or another person's data.

If private vulnerability reporting is not available, open a minimal issue titled **Private security contact requested** in the affected repository. Do not put exploit details, credentials, or personal data in that issue; maintainers can arrange a private channel.

For a suspected exposed credential, revoke or rotate the credential through its provider as soon as possible. Removing it from the latest commit does not remove it from Git history.

We may coordinate a fix and disclosure with the reporter. Please give maintainers a reasonable opportunity to investigate before publishing exploit details. No response or remediation deadline is promised.
